# HardcoverSync

Supernote plugin that sends the reading position of the EPUB open in DOC to Hardcover (hardcover.app). The account is signed in on the device (OAuth device grant, see "Sign-in"); the package holds only a public client id. Workspace-wide rules are in `../../CLAUDE.md`; SDK how-tos are in the `supernote-plugin` skill.

## How it works

`index.js` is only the entry point the build scripts bundle; `src/plugin.ts` wires the SDK, and everything else is SDK-free and unit tested (`npx jest`). The whole plugin is TypeScript except `src/plugin.ts`, the config files and the generated `src/clientId.generated.js`; `npx tsc --noEmit` checks it.

- Tracking is touch-driven, with no timer and no button press needed once a book is switched on: `registerMotionListener` fires on every finger-down, the plugin reads file path, page and total, and `src/tracker.ts` decides when to push. Tracking is per document and OFF by default: the page's toggle turns it on for the open book, and the flag is saved as `tracking` in that file's entry of `meta-cache.json` (next to the edition; the entry is dropped when the file size changes, which resets it to off). A book that is off is ignored on touches. Turning it on or off calls `tracker.forget(path)`, so a book is never pushed on the touch right after switching it on. A lost sign-in (`SignedOutError`, or a 401 the refresh could not fix) stops all tracking until the page signs in again.
- Push rules (owner decisions; same idea as the KOReader plugin's percentage mode): never on first sight of a book; every change of the edition page is pushed (position = `(page + 1) / total`, so font size and orientation do not matter), both directions, at most one push per 10 s per book (`PUSH_INTERVAL_MS` in `src/tracker.ts`, checked against timestamps at touch time, no timer). A page turned inside the window stays pending (latest wins) and goes out at the first touch after it; going back to the pushed page clears it. Hardcover merges the updates into one journal entry. A page turned at the last tap is only seen at the next finger-down, so it goes out at the next touch.
- Button `Hardcover` (id 100, `showType: 1`) opens the detail page full screen (`App.tsx` + `src/ui/DetailPage.tsx`). `onButtonPress` fires too: it samples the open document (`session.pending`) before the view covers it. plugin.ts and the page share one JS runtime, so plugin.ts hands the page its functions through `src/session.ts` (`session.api`: load, setStatus, setEdition, setTracking, writeReview, saveReview); the page never sees the SDK or the token. `load()` = sample -> `resolvePath` -> `fetchBookDetail` -> `buildDetail` (`src/detail.ts`). A book that is not in the library is looked up in the whole catalogue (`catalogueBook` in `src/resolve.ts`: ISBN first, else title + author search). The first time, a Yes/No dialog asks whether to add it (only from a button press, `linkFromCatalogue` in plugin.ts; a touch never opens a dialog): Yes adds it with `addOwned` (`src/hardcover.ts`): the edition goes on the Owned list (`markOwned`, creates no library entry), then `library.add` makes the entry. Hardcover cannot create an entry without a status and gives Want to Read (checked 2026-11-10); a book already in the library is never touched. On No the book stays linked per file (`linked: {bookId, editionId?}` in that file's `meta-cache.json` entry, like KOReader's link; no second prompt): the page and journal work for it, but tracking and status need a library entry (progress and status take a `userBookId`), so the page hides them and shows an Add to library button (`session.api.addToLibrary`) instead. Only when the catalogue has no match either, a message "This book is not in your Hardcover library." shows, as does an EPUB whose title cannot be read (a button press reads it again; touches do not, until a restart). A line above the progress bar (`sync` from `load()`) shows "Last sync: page N", the last error or "Token rejected, tracking stopped", for the open file only (errors and pushes are tagged with the file path). The edition list also holds the editions the reader already uses (`mine` query) and hides those with no page count. The old status dialog (pause/resume, last sync, last error) is gone: the Tracking toggle on the page replaces it.
- Edition per file: picking one in the page stores `{id, pages}` as `edition` inside the file's entry of the metadata cache (`meta-cache.json`, so it is dropped when the file size changes), and `withEdition` applies it to the reading item, so pages are computed and sent against that edition (`edition_id` on the read). Changing it calls `tracker.forget(path)`. The status picker writes `update_user_book(status_id)` after a confirmation dialog for anything but Currently reading (Cancel leaves the status alone; the book leaves the list the plugin works from); ids 1 want to read, 2 reading, 3 read, 5 did not finish are confirmed on the account (via `user_book_status`), 4 (Paused) is unused here and only known from third-party docs.
- Which book: `src/epub.ts` reads title/author/ISBNs from the EPUB with a few range reads (never the filename). `src/resolve.ts`: an ISBN-13 that Hardcover knows decides it (that book is either being read or not), else title + author against the books in the library (`src/match.ts`; with overlapping titles by one author the longer one wins, "Dune Messiah" over "Dune"). The tracker looks every book up again after 10 minutes (`RECHECK_MS`), matched or not; a failed re-check keeps the old item, and a book that left the list stops pushing.
- Progress = `round((page + 1) / total * edition pages)`, written against the edition on the user's reading entry (`src/hardcover.ts`, typed `operations.UpdateUserBookRead`/`AddUserBookRead`, existing non-null fields sent back). The tracker compares in these edition pages, not reader pages, so a font or orientation change (which changes `total`) neither stalls nor double-pushes.
- Each touch reads the file path twice around the page and total and drops the sample if it changed, so a book switch cannot pair one book's path with another's page.
- Native module `HardcoverNative` (`android/app/src/main/java/com/hardcoversync/`, registered with `add(HardcoverNativePackage())` in `MainApplication.kt`): `readTextFile` ("" if missing), `writeFile` (temp file + rename, creates folders), `stat` ({exists, size}; deliberately no mtime: the document app updates it every time a book is opened). Used through `src/store.ts` (SDK-free, injected adapter, never throws; with no module or a failing call everything falls back to memory, so tracking never depends on it). Persisted: the EPUB metadata cache in the plugin's private directory (`meta-cache.json`, no permission needed, keyed by path and valid only while the file size is unchanged, capped at 300 entries). `createSettings` (a `MyStyle/Plugins/HardcoverSync/settings.json` that survives reinstalls, needs FILE:WRITE requested from a button press) is kept in `src/store.ts` but unused since privacy became a per-entry choice.
- Button `hardcover-select` (id 300, selection toolbar type 3, DOC, `showType: 1`; labels are not shown on the device): opens `src/ui/JournalPage.tsx`, one "Add journal entry" card like hardcover.app's, with Note | Quote tabs (opens on Quote). `onButtonPress` reads the selection (`session.selection`, cleaned by `cleanQuote`) and the sample before the view covers it and sets `session.mode = 'journal'`; App then loads the book like the detail page and shows the journal page. Quote: the passage shown read-only plus optional thoughts. Note: only your text, no passage. Edition row opens the shared `src/ui/EditionPicker.tsx` (changes the file's edition, same as the detail page). Privacy per entry, default Private, not remembered. No tags, no date (the server stamps now). Saved with `saveJournal` (`src/hardcover.ts`); entry text and position come from `src/journal.ts`. Not yet tried on the device: whether the page shows behind the card, TextInput and the keyboard in a plugin view, and `getLastSelectedText` from a type 3 press with `showType: 1`.
- Review: the Write review button (`writeReview`, needs a library entry, else "add the book to your library first") opens `src/ui/ReviewPage.tsx` like hardcover.app's edit form: star rating (tap or drag across five stars, half steps; tapping the current rating clears it; a half star is the solid star clipped over the outline star because the Nomad font has no half-star glyph, U+2BEA etc. draw as boxes, measured with a probe 2026-11-11), review text, spoilers and Sponsored/ARC checkboxes side by side, private notes box, Saving/Saved/Retry. The card starts from what the entry holds (`fetchReview` = `library.get`: rating, text, spoilers, notes; the sponsored flag is not returned, so it starts unchecked) and saving replaces it. `saveReview` in `src/hardcover.ts` is one typed `operations.UpdateUserBook` (`library.update` has no sponsored flag): `review_markdown`, `review_has_spoilers`, `private_notes` (an emptied box clears them), `rating` only when set, `sponsored_review` only when checked; empty text refused. Inline spoiler blur, review date, URLs and reads are not implemented. Design board: "PR #56: Write review" in the design artifact. Not yet tried on the device or against the live API.
- Journal format (verified 2026-11-10 with three private test posts on the owner's account and against public entries): `insert_reading_journal` with `event` `quote` or `note`; `tags` is REQUIRED (send `[]`); a quote with thoughts is `passage + "\n\n━━━\n\n" + thoughts` in one `entry` (hardcover.app draws ━━━ as a divider, other clients write the same) and stays `event: quote`; position goes in `metadata.position = {type: "pages", value: edition page, percent, possible: edition pages}` and shows as "p. 83". `{page}` in metadata (the old guess) is wrong.

## Measured on the Nomad (firmware 3.29.x, sn-plugin-lib 0.1.65, 2026-11-09)

- **Timers vs events (the key fact):** `setTimeout`/`setInterval` run only in lifecycle state 2 (after a button press; not at boot, not after a view closed = state 3). `registerMotionListener` touch events and SDK calls (path, page, total) work in ALL states, including before any press and after a view closed. So anything that must happen later is decided from timestamps at the next touch, and a view (showType 1) can be used without stopping tracking. Unexplained: during one early probe the timer was silent for about 7 minutes with the device on the home screen or locked.
- A `showType: 1` view is full-screen: `regionType: 1` (center dialog) with `regionWidth: 720, regionHeight: 540` was ignored (layout 749x998 dp = whole window, 2026-11-09). The SDK documents regionType 0 none, 1 center dialog, 2 fullscreen, 3 fullscreen not dismissed; SuperDashboard and the dictionary plugin also get a fullscreen view.
- Gestures (tap, finger swipe, two-finger swipe are the options; measured): every gesture starts with one finger-down (action 0, tool 1) and ends with a plain up (action 1). Two-finger swipes add action 261 and 5/6 or 262 (the pointer index is in the high byte). The reader flips the page a few ms to about 1 s AFTER the up, so a read at the up is often the old page; a read at the next finger-down is always current. A touch-driven read is therefore one gesture behind: `tracker.js` counts a page change from the PREVIOUS read.
- `showRattaDialog(tip, left, right, ok)` resolves `false` for the left button and `true` for the right (also confirmed by Ink2Task).
- `getCurrentPageNum` is 0-based. In a note the page works but `getCurrentTotalPages` errors ("not allowed"); with the screen asleep it errors ("handwriting app is not open"). With Settings in front, SDK calls hang: every call has a timeout.
- `getLastSelectedText` works on EPUBs; the text has a `\n` at every page line wrap (`src/quote.ts` joins them) and may start mid-word.
- `fetch('file://...')` works with FILE:READ, ignores `Range`. `fetch -> blob() -> blob.slice() -> FileReader` reads only the slice into JS: about 70 KB and 0.4 s per book instead of 5 s for the whole file.
- No JS file write exists in the SDK, React Native or the host (no fs library), hence the native module above. Verified on the Nomad 2026-11-09: write, read-back and stat round trip in the private dir; settings.json created in MyStyle after the FILE:WRITE grant; after a plugin restart (Settings > Apps > Plugins > the ON switch off and on) the first touch logs "metadata from the saved cache" 61 ms after the touch instead of a 350-500 ms EPUB read.
- `adb shell input tap` does NOT reach the plugin's touch listener; only real touches do, so tracking cannot be driven or tested with injected taps.
- Hardcover: a progress update creates one public `progress_updated` journal entry, and later updates merge into it: 17 s apart, and also an update 71 minutes later the same day updated the same entry in place (window longer than that, probably the day). Account default privacy is Public. ISBNs differ between files and the user's chosen editions, and file metadata can hold typo ISBNs (Circe), so ISBN and title/author are both needed.

## Sign-in (OAuth device grant, RFC 8628)

No token ships in the package. `src/plugin.ts` builds an `OAuthSession` (`@hardcover/sdk/oauth`, public client id from `HARDCOVER_OAUTH_CLIENT_ID` in the root .env via `scripts/write-client-id.js`, no secret) and passes it to every call in `src/hardcover.ts` as the client's `auth`: the session refreshes before expiry on the next call (no timer, so it works in every lifecycle state), replays a 401 once, runs one refresh at a time and stores the rotated refresh token. Tokens live in `tokens.json` in the plugin's private dir (`fileTokenStore` in `src/auth.ts`, same JsonFile as the meta cache; written with `strict` so a failed write rejects instead of leaving a stale refresh token; without the native module they are memory only and a restart signs out). Scopes (`SCOPES` in `src/auth.ts`): read:me:content, read:library, write:library, read:catalog, write:reviews (review card), taken from the SDK's per-call docs. Sign-ins stored before write:reviews was added lack it: `writeReview` checks `oauth.tokens().scope` (`hasScope`) and, if missing, asks in a dialog, signs out and reloads to the Sign in button. A button press with no stored tokens shows "Sign in to Hardcover" with a Sign in button (`session.api.signIn`): the page shows the verification URL, the code and a QR code of `verification_uri_complete` (`src/ui/QrCode.tsx`, `qrcode-generator`, pure JS drawn with Views, no native code) while the SDK polls (timers run after a button press), then reloads. Pressing the button again (a reload) aborts the waiting attempt (`signInAbort` in plugin.ts), so the Sign in button comes back. The pending sample and the selection are kept through the sign-in (load checks it first), and a successful sign-in calls `tracker.reset()` (cached items hold the old account's ids, the last error is cleared). The old personal token (`HARDCOVER_KEY`, `write-token.js`) is gone with no fallback: the first run after updating asks for a sign-in. Not yet tried on the device: the real scopes list against the account's client, and the refresh path (needs an access token to expire).

## Hardcover client

`src/hardcover.ts` is the only file that talks to Hardcover, through `@hardcover/sdk` (pinned 0.1.1, ESM only, jest transforms it). Library, book/edition reads, status and quotes use its resources (`library.list`, `books.get/editions/edition/findByIsbn`, `library.setStatus`, `journal.add`); the progress write uses the typed operations because `reads.setProgress` takes no edition or dates and throws without a read in progress. The client is created with `pace: false` (the SDK would wait with `setTimeout`, which only runs in lifecycle state 2) and `maxRetries: 0` (the tracker owns retries). SDK errors carry `status`. Known losses from the old raw queries: the detail page no longer shows the reviews count (`Book` has no such field). Status ids come from the SDK's `UserBookStatus` (Paused = 4 is defined there).

## Build and install

```powershell
Remove-Item Env:NoDefaultCurrentDirectoryInExePath   # this machine sets it to 1, so cmd cannot run gradlew.bat from the current folder; clearing it affects only this PowerShell process
npm run build          # writes src/clientId.generated.js from ../../.env (HARDCOVER_OAUTH_CLIENT_ID), then scripts/buildPlugin.ps1 (Gradle: JDK 17, platform 35, build-tools 35.0.0, NDK 27.1.12297006, Gradle 8.13 via the wrapper)
```

Push from Git Bash with `MSYS_NO_PATHCONV=1` (it rewrites `/storage/...` paths), or from PowerShell: `adb -s SN078E10048537 push build\outputs\HardcoverSync.snplg /storage/emulated/0/MyStyle/HardcoverSync.snplg`. The first native build took 46 s here (Gradle was cached); the package is about 7 MB (a 6.9 MB `app.npk` plus the 1.1 MB bundle).

Install with Settings > Apps > Plugins > Add Plugin (not "reinstall"). Feature PRs target `dev` (squash-merged, conventional title). Releasing = a PR `dev` to `master` merged with a **merge commit** (not squash, so every feat/fix title reaches master); the push to master releases automatically; for testers, run the Release workflow by hand on `dev` (`gh workflow run release.yml --ref dev`) to publish a `vA.B.C-CODE-dev` pre-release, versioned by CI from the conventional commits since the last tag (`scripts/next-version.js`: feat minor, fix patch, breaking major; docs/chore/ci/perf/refactor release nothing); the checked-in version is only a baseline and CI never commits back. For local device builds, still bump `versionCode` (and `versionName`/`package.json` together) every install (29 in `PluginConfig.json` now; the installer refuses a lower or equal code with "This plugin version is too low"). The branch is `master`. The package is megabytes because of the native module; if you ever go back to JS-only, delete `build/` first or a stale `app.npk` is zipped into it silently. `src/clientId.generated.js` and `build/` are gitignored. The emulator is usually running too, so always `adb -s <serial>`.

Branding assets in `assets/` come from the Hardcover press kit (hardcover.app/pages/about): `icon.png` (toolbar buttons, from `logo-line-white.png` cropped so the outline touches the edges and thickened by 2 source px, 96x96), `plugin-icon.png` (`iconPath`, same treatment, 192x192; black outline, suits the greyscale e-ink screen), `logo.png` (detail page top bar, from `Hardcover OneColor Dark.png`). Not yet checked on the emulator or the Nomad.

## Detail page and emulator preview

`src/ui/DetailPage.tsx` is the book detail page, ported from the settled design artifact: top bar with a Tracking ON/OFF toggle, progress bar with the text inside, cover and info, one-line Genre/Mood/Tags rows (pills that do not fit become a `+x` pill, measured in a hidden layer), a status button that opens a full-screen status list, an edition row that opens a full-screen edition list (editions with no page count, audiobooks included, hidden; Cancel / Use this edition), About clamped to 5 lines with Show more, a fixed Write review bar, and a tappable cover that opens a full-screen cover view (`view === 'cover'`, tap anywhere or ✕ to return; no cover, no button). Presentational (props only, no SDK), black on white with borders, tap targets of at least 48 dp. The chosen edition belongs in the existing path-keyed metadata cache (`meta-cache.json`), not a new file-hash cache. `src/ui/mockBook.js` has the real Hardcover record of The Butcher of Nazareth with its editions and a worst case. Status ids: 1, 2, 3 and 5 are confirmed on the account, 4 (Paused) is not (see "How it works").

To design it at the Nomad's real size, follow the "Emulator" section of the workspace CLAUDE.md. For this project: Metro with `$env:SN_FAKE_SDK = '1'; npx --no-install react-native start --reset-cache` (a Metro for this project may already be running on 8081: check `curl localhost:8081/status`, and do not start a second one), install `android\app\build\outputs\apk\debug\app-debug.apk` on the emulator only (`adb -s emulator-5554 install -r ...`, all ABIs were built), `adb -s emulator-5554 reverse tcp:8081 tcp:8081`, then `adb -s emulator-5554 shell am start -n com.hardcoversync/.MainActivity`. JS edits reload through Metro (or force-stop and start the app). In preview, the Write review button opens the review card, the toggle flips ON/OFF and the normal/worst-case mock, and the close button opens the journal card with a mock passage (saves alternate between success and a failure); adb taps work on the emulator (not on the Nomad). Rebuild the APK only when native code changes.

Design findings (emulator, 1404x1872): everything fits on one screen with the action bar fixed at the bottom, so scrolling (slow on e-ink) is only needed for the extreme case; a `showType: 1` view is full-screen on the Nomad (regionType is ignored), and the emulator shows a status bar the Nomad view will not have.
