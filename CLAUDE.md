# HardcoverSync

Supernote plugin that sends the reading position of the EPUB open in DOC to Hardcover (hardcover.app). Personal build: it carries the owner's API token, so a built `.snplg` must never be shared. Workspace-wide rules are in `../../CLAUDE.md`; SDK how-tos are in the `supernote-plugin` skill.

## How it works

`index.js` wires the SDK; everything else is SDK-free and unit tested (`npx jest`).

- Tracking is touch-driven, with no timer and no button press needed once a book is switched on: `registerMotionListener` fires on every finger-down, the plugin reads file path, page and total, and `src/tracker.js` decides when to push. Tracking is per document and OFF by default: the page's toggle turns it on for the open book, and the flag is saved as `tracking` in that file's entry of `meta-cache.json` (next to the edition; the entry is dropped when the file size changes, which resets it to off). A book that is off is ignored on touches. Turning it on or off calls `tracker.forget(path)`, so a book is never pushed on the touch right after switching it on. A 401 from Hardcover stops all tracking until the plugin restarts.
- Push rules (owner decisions; same idea as the KOReader plugin's percentage mode): never on first sight of a book; progress is sent each time you cross a 2% step of the book (`STEP_PERCENT` in `src/tracker.js`; position = `(page + 1) / total`, so font size and orientation do not matter), and it sends your CURRENT page on the edition, not the step boundary; both directions; no timer, no dwell, no interval, no throttle. A few pages inside one step never push, so accidental turns are harmless. Hardcover can lag by up to one step; there is no extra push after a long break (offered, not wanted). A page turned at the last tap is only seen at the next finger-down, so a crossing goes out at the next touch.
- Button `Hardcover` (id 100, `showType: 1`) opens the detail page full screen (`App.tsx` + `src/ui/DetailPage.tsx`). `onButtonPress` fires too: it samples the open document (`session.pending`) before the view covers it. index.js and the page share one JS runtime, so index.js hands the page its functions through `src/session.js` (`session.api`: load, setStatus, setEdition, setTracking, writeReview); the page never sees the SDK or the token. `load()` = sample -> `resolvePath` -> `fetchBookDetail` -> `buildDetail` (`src/detail.js`). A book that is not on the Currently Reading list shows a message instead, as does an EPUB whose title cannot be read (a button press reads it again; touches do not, until a restart). A line above the progress bar (`sync` from `load()`) shows "Last sync: page N", the last error or "Token rejected, tracking stopped", for the open book only. The edition list also holds the editions the reader already uses (`mine` query) and hides those with no page count. The old status dialog (pause/resume, last sync, last error) is gone: the Tracking toggle on the page replaces it.
- Edition per file: picking one in the page stores `{id, pages}` as `edition` inside the file's entry of the metadata cache (`meta-cache.json`, so it is dropped when the file size changes), and `withEdition` applies it to the reading item, so pages are computed and sent against that edition (`edition_id` on the read). Changing it calls `tracker.forget(path)`. The status picker writes `update_user_book(status_id)` after a confirmation dialog for anything but Currently reading (Cancel leaves the status alone; the book leaves the list the plugin works from); ids 1 want to read, 2 reading, 3 read, 5 did not finish are confirmed on the account (via `user_book_status`), 4 (Paused) is unused here and only known from third-party docs.
- Which book: `src/epub.js` reads title/author/ISBNs from the EPUB with a few range reads (never the filename). `src/resolve.js`: an ISBN-13 that Hardcover knows decides it (that book is either being read or not), else title + author against the Currently Reading list (`src/match.js`; with overlapping titles by one author the longer one wins, "Dune Messiah" over "Dune"). The tracker looks every book up again after 10 minutes (`RECHECK_MS`), matched or not; a failed re-check keeps the old item, and a book that left the list stops pushing.
- Progress = `round((page + 1) / total * edition pages)`, written against the edition on the user's reading entry (`src/hardcover.js`, `update_user_book_read`, existing non-null fields sent back). The tracker compares in these edition pages, not reader pages, so a font or orientation change (which changes `total`) neither stalls nor double-pushes.
- Each touch reads the file path twice around the page and total and drops the sample if it changed, so a book switch cannot pair one book's path with another's page.
- Native module `HardcoverNative` (`android/app/src/main/java/com/hardcoversync/`, registered with `add(HardcoverNativePackage())` in `MainApplication.kt`): `readTextFile` ("" if missing), `writeFile` (temp file + rename, creates folders), `stat` ({exists, size}; deliberately no mtime: the document app updates it every time a book is opened). Used through `src/store.js` (SDK-free, injected adapter, never throws; with no module or a failing call everything falls back to memory, so tracking never depends on it). Persisted: the EPUB metadata cache in the plugin's private directory (`meta-cache.json`, no permission needed, keyed by path and valid only while the file size is unchanged, capped at 300 entries) and settings in `MyStyle/Plugins/HardcoverSync/settings.json` (`quotePrivacy`, default 3 = private; survives reinstalls; needs FILE:WRITE, which is requested only from a button press, because a dialog from a touch handler is untested). The settings file is created when quotes are first used.
- Button `Save quote` (id 300, selection toolbar, DOC): built and unit tested but OFF (`QUOTES_ENABLED = false` in `index.js`). The journal `event` string (`quote`) and where the page goes in `metadata` are unverified (the owner said no test quote is needed, which leaves open whether to enable quotes anyway). Quotes default to private (privacy id 3).

## Measured on the Nomad (firmware 3.29.x, sn-plugin-lib 0.1.65, 2026-11-09)

- **Timers vs events (the key fact):** `setTimeout`/`setInterval` run only in lifecycle state 2 (after a button press; not at boot, not after a view closed = state 3). `registerMotionListener` touch events and SDK calls (path, page, total) work in ALL states, including before any press and after a view closed. So anything that must happen later is decided from timestamps at the next touch, and a view (showType 1) can be used without stopping tracking. Unexplained: during one early probe the timer was silent for about 7 minutes with the device on the home screen or locked.
- A `showType: 1` view is full-screen: `regionType: 1` (center dialog) with `regionWidth: 720, regionHeight: 540` was ignored (layout 749x998 dp = whole window, 2026-11-09). The SDK documents regionType 0 none, 1 center dialog, 2 fullscreen, 3 fullscreen not dismissed; SuperDashboard and the dictionary plugin also get a fullscreen view.
- Gestures (tap, finger swipe, two-finger swipe are the options; measured): every gesture starts with one finger-down (action 0, tool 1) and ends with a plain up (action 1). Two-finger swipes add action 261 and 5/6 or 262 (the pointer index is in the high byte). The reader flips the page a few ms to about 1 s AFTER the up, so a read at the up is often the old page; a read at the next finger-down is always current. A touch-driven read is therefore one gesture behind: `tracker.js` counts a page change from the PREVIOUS read.
- `showRattaDialog(tip, left, right, ok)` resolves `false` for the left button and `true` for the right (also confirmed by Ink2Task).
- `getCurrentPageNum` is 0-based. In a note the page works but `getCurrentTotalPages` errors ("not allowed"); with the screen asleep it errors ("handwriting app is not open"). With Settings in front, SDK calls hang: every call has a timeout.
- `getLastSelectedText` works on EPUBs; the text has a `\n` at every page line wrap (`src/quote.js` joins them) and may start mid-word.
- `fetch('file://...')` works with FILE:READ, ignores `Range`. `fetch -> blob() -> blob.slice() -> FileReader` reads only the slice into JS: about 70 KB and 0.4 s per book instead of 5 s for the whole file.
- No JS file write exists in the SDK, React Native or the host (no fs library), hence the native module above. Verified on the Nomad 2026-11-09: write, read-back and stat round trip in the private dir; settings.json created in MyStyle after the FILE:WRITE grant; after a plugin restart (Settings > Apps > Plugins > the ON switch off and on) the first touch logs "metadata from the saved cache" 61 ms after the touch instead of a 350-500 ms EPUB read.
- `adb shell input tap` does NOT reach the plugin's touch listener; only real touches do, so tracking cannot be driven or tested with injected taps.
- Hardcover: a progress update creates one public `progress_updated` journal entry, and later updates merge into it: 17 s apart, and also an update 71 minutes later the same day updated the same entry in place (window longer than that, probably the day). Account default privacy is Public. ISBNs differ between files and the user's chosen editions, and file metadata can hold typo ISBNs (Circe), so ISBN and title/author are both needed.

## Build and install

```powershell
Remove-Item Env:NoDefaultCurrentDirectoryInExePath   # this machine sets it to 1, so cmd cannot run gradlew.bat from the current folder; clearing it affects only this PowerShell process
npm run build          # writes src/token.generated.js from ../../.env (HARDCOVER_KEY), then buildPlugin.ps1 (Gradle: JDK 17, platform 35, build-tools 35.0.0, NDK 27.1.12297006, Gradle 8.13 via the wrapper)
```

Push from Git Bash with `MSYS_NO_PATHCONV=1` (it rewrites `/storage/...` paths), or from PowerShell: `adb -s SN078E10048537 push build\outputs\HardcoverSync.snplg /storage/emulated/0/MyStyle/HardcoverSync.snplg`. The first native build took 46 s here (Gradle was cached); the package is about 7 MB (a 6.9 MB `app.npk` plus the 1.1 MB bundle).

Install with Settings > Apps > Plugins > Add Plugin (not "reinstall"). Bump `versionCode` (and `versionName`/`package.json` together) every install (26 in `PluginConfig.json` now). The branch is `master`. The package is megabytes because of the native module; if you ever go back to JS-only, delete `build/` first or a stale `app.npk` is zipped into it silently. `src/token.generated.js` and `build/` are gitignored. The emulator is usually running too, so always `adb -s <serial>`.

## Detail page and emulator preview

`src/ui/DetailPage.tsx` is the book detail page, ported from the settled design artifact: top bar with a Tracking ON/OFF toggle, progress bar with the text inside, cover and info, one-line Genre/Mood/Tags rows (pills that do not fit become a `+x` pill, measured in a hidden layer), a status button that opens a full-screen status list, an edition row that opens a full-screen edition list (editions with no page count, audiobooks included, hidden; Cancel / Use this edition), About clamped to 5 lines with Show more, and a fixed Write review bar. Presentational (props only, no SDK), black on white with borders, tap targets of at least 48 dp. The chosen edition belongs in the existing path-keyed metadata cache (`meta-cache.json`), not a new file-hash cache. `src/ui/mockBook.js` has the real Hardcover record of The Butcher of Nazareth with its editions and a worst case. Status ids: 1, 2, 3 and 5 are confirmed on the account, 4 (Paused) is not (see "How it works").

To design it at the Nomad's real size, follow the "Emulator" section of the workspace CLAUDE.md. For this project: Metro with `$env:SN_FAKE_SDK = '1'; npx --no-install react-native start --reset-cache` (a Metro for this project may already be running on 8081: check `curl localhost:8081/status`, and do not start a second one), install `android\app\build\outputs\apk\debug\app-debug.apk` on the emulator only (`adb -s emulator-5554 install -r ...`, all ABIs were built), `adb -s emulator-5554 reverse tcp:8081 tcp:8081`, then `adb -s emulator-5554 shell am start -n com.hardcoversync/.MainActivity`. JS edits reload through Metro (or force-stop and start the app). In preview, the Add note button flips between the normal and the worst-case mock, and the toggle flips ON/OFF; adb taps work on the emulator (not on the Nomad). Rebuild the APK only when native code changes.

Design findings (emulator, 1404x1872): everything fits on one screen with the action bar fixed at the bottom, so scrolling (slow on e-ink) is only needed for the extreme case; a `showType: 1` view is full-screen on the Nomad (regionType is ignored), and the emulator shows a status bar the Nomad view will not have.
